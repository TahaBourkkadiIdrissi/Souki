# Audit SEO SOUKI — 27 septembre 2026

Audit demandé à partir de `SOUKI_SEO_AUDIT_PLAN.md`, réalisé sur le dépôt, le site public et les interfaces Google accessibles dans Chrome. Aucun réglage externe ni code de production n'a été modifié.

**Périmètre réel.** Le plan nomme `front-end`, mais `docker-compose.yml` construit `apps/client` pour `souki.io`, `apps/admin` pour l'administration et `apps/livreur` pour les livreurs. `front-end` est une ancienne application : elle n'a ni `app/robots.ts` ni `app/sitemap.ts`, et son catalogue est un composant client. Les statuts ci-dessous portent sur **l'application déployée `apps/client`**. Appliquer littéralement les tests de fichiers du plan à `front-end` donnerait des échecs qui ne décrivent pas la production.

## Sprint 1 — code

| Contrôle | Statut | Preuve et détail |
|---|---|---|
| A1 `robots.ts` | ✅ PASS | `apps/client/app/robots.ts` autorise `/`, bloque `/backend/` et `/api/`, ne bloque pas `/_next/`, et annonce le sitemap. Les pages privées restent explorables pour que Google lise leur `noindex`. |
| A2 `sitemap.ts` | ⚠️ PARTIEL | `apps/client/app/sitemap.ts` lit dynamiquement les produits actifs via `apps/client/lib/seo-catalogue.ts`, sans URL privée. **Aucune** des 32 URL n'a de `lastModified`, contrairement au plan. `Documentation/SEO_DEPLOYMENT.md` précise que le modèle produit n'a pas de date `updated_at` et qu'il ne faut pas inventer cette donnée. |
| A3 `noindex` privé | ✅ PASS | `apps/client/lib/private-metadata.ts` définit `index: false, follow: false`. Il est utilisé par les layouts de `/checkout`, `/verify`, `/login`, `/parametres` et d'autres routes privées. `apps/admin/app/layout.tsx` et `apps/livreur/app/layout.tsx` font de même. |
| A4 catalogue serveur et liens produit | ✅ PASS | `apps/client/app/catalogue/page.tsx` est un Server Component : il lit le catalogue côté serveur et passe `initialProducts` au composant interactif. `apps/client/app/produit/[slug]/page.tsx` existe et rend les fiches côté serveur. Cache de la réponse API : 3 600 s dans `seo-catalogue.ts`; la page est `force-dynamic`, donc **pas d'ISR de page**. Les cartes produit disposent de liens `<Link href={productPath(product)}>` ; aucun `onClick` de navigation produit n'a été trouvé dans `apps/client`. |
| A5 métadonnées | ✅ PASS | Accueil (`app/page.tsx`), catalogue et produit exportent `metadata` ou `generateMetadata`, avec URL canonique. `app/layout.tsx` fixe `lang="fr"` et `metadataBase=https://souki.io`. |
| A6 JSON-LD | ⚠️ PARTIEL | `app/layout.tsx` : `Organization`, `WebSite`, `Service` ; `app/produit/[slug]/page.tsx` : `Product` avec `Offer` ; `app/faq/page.tsx` : `FAQPage`. Le `LocalBusiness` attendu par le plan est absent. Sur une fiche produit testée, Google détecte un élément Product valide avec avertissements facultatifs détaillés plus bas. |
| A7 configuration images | ⚠️ À OPTIMISER | Six fichiers de `apps/client/app` et `apps/client/components` importent `next/image`. `apps/client/next.config.mjs` contient `images: { unoptimized: true }`. La mesure mobile ci-dessous montre un LCP élevé et des économies d'images estimées à 1,7 Mo sur l'accueil et 5,0 Mo sur le catalogue. |

## Décision proposée

Le Sprint 1 n'est **pas entièrement conforme** au plan : `lastModified` manque faute de date source, `LocalBusiness` est absent, et les performances mobiles restent sous la cible. Le blocage SEO le plus immédiat est cependant la **découverte des pages** : sitemap public présent mais non soumis dans Search Console, catalogue et produits indexables en direct mais inconnus de l'index.

Ordre de travail recommandé après validation du diagnostic :

1. Soumettre `https://souki.io/sitemap.xml` dans Search Console, puis suivre l'état et demander l'indexation du catalogue et de quelques produits prioritaires.
2. Réduire le LCP mobile, en commençant par les images signalées par PageSpeed ; refaire les mesures accueil/catalogue.
3. Décider si le modèle produit doit porter un `updated_at` fiable avant d'ajouter `lastModified` ; décider si un schéma `LocalBusiness` décrit exactement l'activité et la zone desservie.
4. Configurer le DNS/TLS de `soukiapp.com` si ce domaine doit rediriger, puis l'ajouter à Search Console ; vérifier Bing et la fiche Google Business avec les comptes propriétaires appropriés.
5. Tester les événements métier GA4 dans DebugView sur un parcours de test maîtrisé et vérifier la politique de cache HTML et les en-têtes dupliqués.

Le rapport décrit l'état observé le 27/09/2026. Les données de classement, d'indexation et de performance évoluent ; les liens PageSpeed ci-dessus pointent vers les exécutions utilisées ici.
